============================================================
                    BACKEND FOLDER
============================================================

FOLDER:
-------
backend/

PURPOSE:
--------
The backend folder contains the server-side logic of the
RSET Connect project.

It is responsible for processing requests from the frontend,
managing application data, performing CRUD operations, and
sending responses back to the frontend.

CRUD stands for:

C - Create
R - Read
U - Update
D - Delete

The backend mainly works with CSV files as the data storage
system.

The backend folder contains:

1. csv/
2. routes/
3. types.ts

============================================================
1. CSV FOLDER
============================================================

FOLDER:
-------
backend/csv/

PURPOSE:
--------
The csv folder contains the files responsible for managing
CSV data used by the backend.

The project uses CSV files instead of a traditional database
to store information such as students, marks, attendance,
announcements, and events.

The csv folder provides common functionality for reading,
writing, updating, and initializing CSV data.


------------------------------------------------------------
1.1 csvService.ts (CONTINUED)
------------------------------------------------------------

WHY IT IS IMPORTANT:
--------------------
Instead of writing separate CSV reading and writing logic
inside every route file, the routes can use the common
functions provided by csvService.ts.

For example:

- attendance.ts uses CSV functions to read attendance data.
- marks.ts uses CSV functions to read and update marks.
- students.ts uses CSV functions to add, update, and delete
  student records.

Therefore, csvService.ts acts as a common utility layer
between the backend routes and the CSV files.

GENERAL FLOW:
-------------

Route File
    |
    v
csvService.ts
    |
    v
CSV File
    |
    v
Data returned to Route File



------------------------------------------------------------
1.2 seedData.ts
------------------------------------------------------------

PURPOSE:
--------
Provides initial or sample data for the application.

MAIN RESPONSIBILITIES:
----------------------
1. Creates sample records.
2. Initializes CSV files with data.
3. Adds sample students.
4. Adds sample attendance information.
5. Adds sample marks.
6. Adds sample announcements.
7. Adds sample subjects and other records.
8. Helps set up the application for development and testing.

WHY IT IS IMPORTANT:
--------------------
When the project is started for the first time, the CSV
files may not contain the required data.

seedData.ts helps populate the CSV files with sample data
so that the application can be tested without entering
everything manually.

DIFFERENCE BETWEEN csvService.ts AND seedData.ts:
-------------------------------------------------

csvService.ts:
- Handles CSV reading and writing operations.
- Provides reusable functions for data management.

seedData.ts:
- Provides initial or sample records.
- Uses data management functions to populate the CSV files.



============================================================
2. ROUTES FOLDER
============================================================

FOLDER:
-------
backend/routes/

PURPOSE:
--------
The routes folder contains the API route files of the
application.

Each route file handles a particular feature or module
of RSET Connect.

For example:

- activities.ts handles student activities.
- attendance.ts handles attendance.
- marks.ts handles student marks.
- students.ts handles student information.
- auth.ts handles authentication.

The route files receive requests from the frontend,
process the requests, access the required CSV files,
and send responses back to the frontend.

GENERAL RESPONSIBILITIES:
-------------------------
1. Receive HTTP requests.
2. Process request data.
3. Validate input.
4. Read information from CSV files.
5. Add, update, or delete records.
6. Send responses to the frontend.
7. Handle errors when required.


GENERAL BACKEND REQUEST FLOW:
-----------------------------

Frontend
    |
    | HTTP Request
    v
Backend Route
    |
    | Read / Write Data
    v
csvService.ts
    |
    v
CSV File
    |
    v
Backend Response
    |
    v
Frontend UI

- Semester.

If incorrect data is passed to a function or variable,
TypeScript can help identify the error during development.



============================================================
4. COMPLETE BACKEND WORKING
============================================================

The backend works as a connection between the frontend
and the CSV data files.

GENERAL FLOW:
-------------

Frontend
    |
    | Sends API Request
    v
Backend Route
    |
    | Processes Request
    v
CSV Service
    |
    | Reads / Writes Data
    v
CSV File
    |
    | Returns Data
    v
Backend Route
    |
    | Sends API Response
    v
Frontend
    |
    v
Updated User Interface


EXAMPLE: ADDING A STUDENT
-------------------------

1. Admin enters student details in the frontend.
2. Frontend sends a POST request to students.ts.
3. students.ts receives the request.
4. The backend validates the submitted information.
5. The CSV service is used to write the data.
6. The new student is added to students.csv.
7. Backend sends a response to the frontend.
8. The student list is updated.


EXAMPLE: DISPLAYING MARKS
-------------------------

1. Student opens the marks page.
2. Frontend sends a request to marks.ts.
3. marks.ts receives the student's UID.
4. The backend reads marks.csv.
5. Subject information may be retrieved from subjects.csv.
6. The backend prepares the response.
7. Marks are sent to the frontend.
8. The frontend displays the student's marks.


EXAMPLE: LOGIN
--------------

1. User enters login details.
2. LoginView.tsx sends the details through AuthContext.
3. AuthContext sends a request to auth.ts.
4. auth.ts checks the information using students.csv.
5. The backend sends a success or failure response.
6. If successful, the user is allowed into the application.

6. IMPORTANT POINTS FOR VIVA
============================================================

1. The backend handles server-side logic and API requests.

2. The routes folder contains separate route files for
   different application features.

3. The CSV folder contains reusable functions for managing
   CSV data.

4. csvService.ts is responsible for common CSV operations.

5. seedData.ts is responsible for inserting initial or
   sample data.

6. The project uses CSV files as its data storage system.

7. The frontend communicates with the backend using
   HTTP requests.

8. The backend reads and modifies CSV files based on
   frontend requests.

9. TypeScript types are defined in types.ts to provide

    when a student is deleted.

    multiple CSV files to display admin dashboard data.

12. The upload.ts route is used to handle uploaded files.

    making the backend organized and easier to maintain.

15. The backend acts as the connection between the
    React frontend and the CSV data storage.
